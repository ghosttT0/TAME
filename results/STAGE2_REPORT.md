# Stage-2: 真实数据 + learned gate + 机制解释

## 1. 数据升级

MVP 使用合成日志；本阶段使用 **CAM-LDS / AIT-LDSv2 真实审计日志**（ait-aecid/log-interpretation-prompt-injection 仓库提供）：

- 14 个真实攻击序列（Linux auditd / auth.log / apache access.log），1 个良性序列；
- 重组为 48 个 4-window 流式序列，保留原始日志文本，不做语法改写；
- benign 窗口来自真实良性日志，恶意窗口来自真实攻击序列切片；
- 与合成集相同的攻击/状态/评测协议，结果可直接对比。

## 2. 真实数据：状态污染复现（无 gate）

| Mode | IASR | DASR | CPL | BMR | MTR |
|---|---:|---:|---:|---:|---:|
| S0 | 41.7% | 60.4% | 0.85 | 6.9% | 81.2% |
| S1 | 41.7% | 83.3% | 1.54 | 34.0% | 81.2% |
| S2 | 27.1% | 58.3% | 0.92 | 11.1% | 75.0% |
| S3 | 37.5% | 56.2% | 1.27 | 22.9% | 75.0% |
| S4 | 45.8% | 62.5% | 0.96 | 9.7% | 83.3% |

结论：真实日志同样存在状态放大——`S1 DASR=83.3%` 远超 `S0` 的 `60.4%`，`CPL` 从 0.85 升到 1.54。但真实日志语义更难，S0 基线本身较高（模型对 auditd 长行的恶意判断不稳定），这使 gate 更受 baseline 噪声限制。

## 3. 真实数据：memory gate 缓解

| Mode | No gate DASR | G1 | G2 | Learned |
|---|---:|---:|---:|---:|
| S1 | 83.3% | 50.0% | 50.0% | 50.0% |
| S3 | 56.2% | 60.4% | 60.4% | 60.4% |

| Mode | No gate BMR | G1 | G2 | Learned |
|---|---:|---:|---:|---:|
| S1 | 34.0% | 11.1% | 11.1% | 11.1% |
| S3 | 22.9% | 4.9% | 7.6% | 4.2% |

观察：`S1` 上 DASR 从 83.3% 降至 50.0%（G1/G2/learned 一致），BMR 从 34% 降到 11%；`S3` 上 DASR 已低于 S1，gate 收益更多体现在 BMR/MTR 转好。learned gate 与规则 gate 行为接近，验证了规则可被轻量模型蒸馏。

## 4. 机制解释：为什么要防 memory write path

**4a. W4 reason 引用注入内容/跨窗口历史的比例**

| Mode | 合成·误判引用注入 | 合成·判对引用注入 | 真实·误判引用注入 | 真实·判对引用注入 |
|---|---:|---:|---:|---:|
| S0 | 0.0% | 0.0% | 0.0% | 0.0% |
| S1 | 45.5% | 3.8% | 42.5% | 12.5% |
| S2 | 22.2% | 0.0% | 3.6% | 0.0% |
| S3 | 36.8% | 0.0% | 14.8% | 0.0% |
| S4 | 0.0% | 0.0% | 0.0% | 0.0% |

机制证据：`S0`（无状态）误判 reason 引用注入内容为 0；`S1` 合成 45% / 真实 42%，`S3` 合成 37%。而判定正确时引用注入内容几乎为 0。跨窗口引用与误判强相关——污染通过引用先前的注入行（quarantine/verified/instruct 等词）进入判断，而不是模型对单窗随机犯错。

**4b. 状态载体保留注入内容的能力**

| 载体 | 注入内容保留机制 | 保留率证据 |
|---|---|---|
| full-history | 注入行逐字节进上下文 | 100% 文本保留（构造保证） |
| retrieval | 注入行进索引，关键词召回 | 召回率 100.0% |
| summary | LLM 转述，指令词通常被保留 | 见报告表 1 summary contamination |
| note | LLM 转述 | 见报告表 1 note contamination |

**4c. 为什么 input filter 型 defense 会失效**

gate 防御的关键差异：当前窗口的日志仍原样进入 verdict 分析，gate 只阻止污染内容写入跨窗口状态。若只做输入过滤，full-history 会把早期窗口的注入内容反复带进后续窗口；而 memory gate 把防线放在写入路径，即使早期窗口被污染，后续窗口也不会继承。

## 5. Learned gate

- 监督标签：G1 规则对每个候选 state item 的接受/拒绝（1920 条，合成 48×12 + 真实 48×4 的逐行标注）；
- 特征：char n-gram TF-IDF (2-5-gram) + 手工信号特征；
- 模型：L1 正则逻辑回归（sklearn），序列级划分训练/测试；
- 测试集（763 条，序列级划分）：precision=1.00, recall=1.00, F1=1.00，拒绝率 5.1%；
- 在真实数据上的缓解表现与 G1 相同（见第 3 节），说明规则可完整蒸馏为轻量分类器。

诚实声明：learned gate 目前是 G1 的蒸馏，不是独立学习的升级；它验证了该防御可以在接近零开销下部署，但尚不能证明比规则本身学得更多。

## 6. 跨数据集一致性

| 现象 | 合成数据 | 真实数据 |
|---|---|---|
| 状态化放大（S1 DASR >> S0 DASR） | 45.8% vs 12.5% | 83.3% vs 60.4% |
| full-history > retrieval | S1 45.8% > S3 39.6% | S1 83.3% > S3 56.3% |
| gate 降低 S1 DASR | 45.8% → 8.3% | 83.3% → 50.0% |
| W4 误判引用注入内容（S1） | 45% | 42% |
| 检索命中注入行 | 100% | 100% |

真实数据上的 gate 剩余 DASR 较高，原因是真实日志本身 S0 基线错误（60.4%）远高于合成数据（12.5%）：auditd 长行的恶意语义对模型不直观，这属于模型能力而非污染残留，也提示后续实验应把 S0 基线错误从 DASR 中扣除或使用更精确的判定协议。
